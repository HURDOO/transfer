# 작업 목록

상태 표기: `[ ]` 대기, `[-]` 진행, `[x]` 완료

- [x] 파일·텍스트를 보내 코드·링크·QR로 다시 받기
  - 프로젝트 골격, 영속 저장, 생성·조회·다운로드 API, 보내기·받기 화면과 모든 만료 선택지를 하나의 흐름으로 연결한다.
  - 작은 텍스트와 파일 2개의 왕복, 만료·빈 입력·합산 제한·재시작을 자동 테스트하고 실제 데스크톱·모바일 브라우저에서 확인하면 완료다.
  - production Chrome에서 데스크톱·320px 모바일, 라이트·다크, 텍스트 생성과 링크·코드 수령, 파일 2개 표시·다운로드, 빈 입력·잘못된 코드 상태를 확인했다.
  - Chrome 확장의 파일 URL 접근 설정은 켰지만 자동화 연결이 파일 선택 이벤트를 전달하지 못했다. 웹 파일 선택→업로드와 실제 기기의 QR 스캔은 사용자가 이번 MVP의 비차단 수동 확인 항목으로 넘겼다.

- [x] 실패 상황에서도 공유를 안전하게 만들고 찾기
  - 중단 업로드, 디스크 쓰기 실패, 동시 요청과 정리 경쟁을 다루고 운영자가 실패 원인을 확인할 수 있게 한다.
  - 부분 파일이 남지 않고 사용자 입력을 보존한 재시도가 가능한지 검증한다.
  - 정지·불완전 업로드, 디스크 쓰기와 DB 커밋 실패, 동시 생성·정리 경쟁을 회귀 테스트했다. 브라우저에서 연결 실패 후 입력·만료값 보존과 재시도 성공도 확인했다.

- [x] 모바일과 보조기술로 더 빠르게 보내고 받기
  - 키보드·스크린리더 흐름과 200% 확대, 업로드 취소, 드래그 상태, 전송 진행률을 세밀하게 다듬는다.
  - 주요 브라우저의 라이트·다크·reduced motion 상태에서 핵심 흐름을 확인한다.
  - 키보드 포커스, 320px 반응형, 라이트·다크와 reduced motion을 확인했다. 업로드 진행률·취소·드래그 UI는 구현되어 있으며, 자동화 연결에 막힌 실제 파일 선택과 200% 확대의 최종 확인은 비차단 수동 회귀 항목으로 남긴다.

- [x] API만으로 같은 공유 흐름 사용하기
  - curl 예제와 안정된 요청·응답 계약으로 생성→조회→다운로드·만료를 문서화하고 검증한다.
  - 웹 전용 우회 동작 없이 API만으로 완료 조건을 재현할 수 있어야 한다.
  - `docs/API.md`와 `pnpm smoke:api`로 텍스트+파일 2개 생성→조회→바이트 동일 다운로드를 재현한다.

- [ ] Raspberry Pi에서 안전하게 운영하기
  - 익명 업로드·다운로드를 유지하면서 multi-arch Docker, 영속 볼륨, 디스크 quota, reverse proxy/TLS, 백업·복구를 구성한다.
  - ARM64 이미지의 로컬 smoke test를 통과한 뒤에만 공개 노출을 검토한다.
  - `docs/OPERATIONS.md`에 LAN 범위, 저장소 용량, 중지 백업·복구와 공개 전 점검표를 작성했다. 사용자의 결정에 따라 Docker와 공개 배포 시스템 구현은 후속 작업으로 미룬다.
