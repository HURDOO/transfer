# 제품 명세

상태: 저장형 MVP와 실시간 파일·텍스트 전송 구현 완료

## 목표와 사용자

`옮기기`는 제3자 파일 전송 서비스 없이 자신이 운영하는 서버에서 파일 묶음이나 텍스트를 공유하고, 6자리 코드·링크·QR로 다시 수령하는 웹 서비스다. 주 사용자는 운영자 한 명이지만, 수령 링크와 API는 코드 소지자에게 공개된다.

## 핵심 사용 흐름

1. 보내는 사람이 파일을 하나 이상 고르거나 텍스트를 입력하고 만료 기한을 선택한다.
2. 서버가 내용을 영속 저장하고 선행 0을 허용하는 6자리 숫자 코드와 공유 링크를 만든다.
3. 화면은 코드, 복사 가능한 링크, 링크를 담은 QR을 보여준다.
4. 받는 사람은 홈의 단일 입력란에 코드를 넣는다. 서버가 코드 종류를 판별해 저장형 수령 또는 실시간 연결 화면을 자동으로 연다. 링크·QR은 해당 수령 화면을 직접 연다.
5. 만료된 공유는 메타데이터 조회와 파일 다운로드 모두 즉시 거부된다.

실시간 모드에서는 보내는 사람이 파일 여러 개와 텍스트 중 하나 이상을 골라 10분짜리 연결 코드·링크·QR을 만들고, 받는 사람 한 명이 들어오면 WebRTC 데이터 채널로 본문을 받는다. 서버는 연결에 필요한 신호만 메모리에 잠깐 중계하며 파일·텍스트 본문은 받거나 저장하지 않는다.

## 기능 요구사항

- 한 공유에 파일 여러 개와 텍스트를 함께 담을 수 있다. 둘 중 하나는 반드시 있어야 한다.
- 만료 기한은 `1시간`, `1일`, `3일`, `1주일`, `30일`, `만료 안 함` 중에서 고른다. 기본값은 1일이다.
- 공유 코드는 정확히 6자리 숫자이며 활성 저장형 공유와 실시간 세션 전체에서 유일하다.
- 웹과 API는 같은 생성·조회·다운로드 계약을 사용한다.
- 업로드 한 번의 파일과 텍스트 합계는 최대 1 GiB다. 파일은 최대 50개, 텍스트는 최대 1 MiB다.
- 원래 파일명은 UTF-8 기준 512바이트까지 표시와 다운로드명으로 보존하되 저장 경로에는 서버가 만든 식별자만 사용한다. 경로 구분자와 제어 문자는 제거한다.
- 저장된 공유는 서버를 재시작해도 유지된다.
- 저장형 공유는 만료 시각에 도달하면 이미 열린 보내기·수령 화면에서도 코드·링크·QR과 내용을 숨기고 보관 종료 화면만 표시한다. 서버는 해당 코드를 즉시 거부하고 만료 데이터 정리 대상으로 처리한다.
- 보내는 화면에서는 `서버에 보관`과 `실시간 연결`을 명시적으로 고른다. 받는 화면은 전송 방식 선택 없이 코드 하나를 입력받아 자동으로 구분한다.
- 실시간 연결 코드는 6자리 숫자이고 10분 뒤 만료되며 한 번에 수령 기기 한 대만 참가할 수 있다.
- 실시간 전송은 저장형과 같은 파일 최대 50개, 텍스트 최대 1 MiB, 합계 최대 1 GiB 제한을 적용한다. 보내는 화면은 수령 확인을 받을 때까지 열려 있어야 한다.
- 실시간 전송은 항목별·전체 진행률과 보내는 쪽·받는 쪽 취소를 지원한다. 완료 파일은 수령 화면에서 개별 다운로드한다.
- 실시간 수령 확인이 끝나면 메모리 세션 코드를 닫는다. 보내는 화면은 코드·링크·QR을 제거하고 완료 화면만 표시하며, 받는 화면은 코드 없이 받은 항목만 표시한다.

## 비기능 요구사항

- 파일 본문을 메모리에 모으지 않고 디스크로 스트리밍한다.
- 만료 여부는 정리 작업과 무관하게 매 조회·다운로드 시 서버 시각으로 판정한다.
- 파일은 `attachment`, `application/octet-stream`, `nosniff`로 내려 인라인 실행을 막는다.
- 코드 조회와 생성 API에 요청 제한을 두고, 로그에 텍스트·파일 내용은 남기지 않는다.
- 라이트·다크 테마, 모바일 320px, 키보드 조작, 명확한 포커스, 상태 알림을 지원한다.
- QR만으로 정보를 전달하지 않으며 코드와 링크를 항상 함께 제공한다.
- `prefers-reduced-motion`에서는 전송 완료 애니메이션을 축소한다.
- 업로드 요청 전체는 30분 안에 끝나야 한다. 멈춘 요청은 `408`로 종료하고 임시 데이터를 제거한다.
- 프록시가 요청 본문 전달을 정상 완료해 입력 스트림을 닫은 경우에는 남은 디스크 쓰기를 계속한다. 본문이 덜 들어온 상태에서 연결이 닫힌 경우에만 업로드를 중단하고 임시 데이터를 제거한다.
- 실시간 본문은 WebRTC 데이터 채널의 DTLS 암호화로 기기 사이를 이동한다. 서버에는 SDP·ICE 후보와 임의 토큰만 10분 동안 메모리로 유지한다.
- 실시간 파일은 최대 64 KiB 청크로 읽고 WebRTC 대기 버퍼를 1 MiB 이하로 유지한다. 수령자는 매니페스트의 순서·개수·파일별 크기·합계 상한을 다시 검증한다.
- STUN/TURN은 운영자가 `LIVE_ICE_SERVERS`로 주입하며 기본값은 외부 ICE 서버 없음이다. 직접 연결이 막힌 네트워크의 안정적 운영에는 자격 증명이 있는 TURN이 필요하다.

## API 계약

### `POST /api/shares`

`multipart/form-data` 요청을 받는다.

- `expiresIn`: `1h | 1d | 3d | 7d | 30d | never`, 필수
- `text`: 선택, UTF-8 최대 1 MiB
- `files`: 선택, 반복 가능한 파일 필드

성공 시 `201`과 코드, 절대 공유 URL, 생성·만료 시각, 선택 텍스트 본문, 파일 메타데이터를 반환한다.

### `GET /api/shares/:code`

텍스트와 파일 다운로드 URL을 포함한 수령 메타데이터를 반환한다.

### `GET /api/shares/:code/files/:fileId`

원래 이름을 사용해 파일을 스트리밍 다운로드한다.

### `GET /api/codes/:code`

활성 저장형 공유와 실시간 세션을 함께 조회해 `{ code, kind: "stored" | "live" }`를 반환한다. 응답은 캐시하지 않으며 존재하지 않거나 만료된 코드는 `404 CODE_NOT_FOUND`다.

### 실시간 연결 API

- `POST /api/live-sessions`: 10분짜리 코드·링크와 보내는 쪽 임의 토큰을 만든다.
- `POST /api/live-sessions/:code/join`: 첫 수령자에게만 받는 쪽 임의 토큰을 발급한다.
- `GET /api/live-sessions/:code/signals`: 토큰과 순서 커서 이후의 SDP·ICE 신호를 조회한다.
- `POST /api/live-sessions/:code/signals`: 상대 피어에게 보낼 SDP·ICE 신호를 등록한다.
- `DELETE /api/live-sessions/:code`: 유효한 피어 토큰으로 메모리 세션을 닫는다.

토큰은 공유 링크에 포함하지 않으며 응답은 캐시하지 않는다. 파일·텍스트 본문은 이 API 계약에 포함되지 않는다.

### 오류

- 빈 공유, 잘못된 만료값·코드·multipart·파일명: `400`
- 총 업로드 제한 초과: `413`
- 업로드 시간 초과: `408`
- 요청 제한 초과: `429`
- 존재하지 않거나 만료된 통합 코드·공유·파일: 정보 노출을 줄이기 위해 `404`
- 코드 공간 예약 실패: `503`
- 예상하지 못한 저장 오류: 내용이 없는 일반화된 `500`

오류 응답은 `{ "error": { "code": string, "message": string } }` 형식이다.

## 현재 범위 제외

- 실시간 전송의 연결 중단 지점 영속 재개
- 상대 기기 신원 확인용 안전 번호 또는 애플리케이션 계층 암호키 검증
- 공유 비밀번호
- 여러 파일 ZIP 다운로드
- 사용자 계정과 관리 화면
- 공개 배포, TLS, 리버스 프록시
- Docker 이미지와 Raspberry Pi 운영 자동화

## 완료 조건

- 작은 텍스트와 파일 2개를 한 번에 공유하면 코드·링크·QR이 표시된다.
- 단일 코드 입력이 저장형과 실시간을 자동 구분한다. 저장형 코드 입력과 직접 링크 모두 같은 수령 화면을 열고, 텍스트 복사와 두 파일 다운로드가 가능하다.
- 직접 API 호출로 생성→조회→다운로드가 동작한다.
- 빈 입력, 잘못된 코드, 합산 크기 제한, 만료, 재시작 영속성에 집중된 테스트가 있다.
- format, lint, typecheck, test, build가 통과한다.
- 데스크톱·모바일, 라이트·다크, 오류·빈 상태를 실제 브라우저에서 확인한다.

실시간 전송의 완료 조건은 코드·링크·QR 생성, 단일 수령자 참가, 파일 2개와 텍스트의 청크 전송·바이트 동일 조립·수령 확인, 완료 뒤 코드 폐기, 진행률·양쪽 취소·제한 초과·실패 상태, 서버 비저장을 검증하는 것이다. 프로토콜과 시그널링은 자동 테스트하고 선택·코드·참가·오류·완료 화면은 production 브라우저로 확인한다. 실제 네트워크 경로는 배포 환경의 STUN/TURN에 종속되므로 운영 배포 smoke에서 일반 브라우저 두 기기로 확인한다.

## 명시된 요구사항과 가정

명시된 요구사항은 여러 파일/텍스트 공유, 6자리 코드와 링크·QR, 여섯 만료 선택지, 웹과 API, 요청당 1GB 제한, 라이트·다크 화면, 로컬 개발과 향후 Raspberry Pi Docker 운영이다.

다음은 이번 구현의 합리적 가정이다.

- `1GB`는 파일 하나가 아니라 공유 요청 전체의 최대 크기이며 이진 단위인 1 GiB로 해석한다.
- `1달`은 30일이며 만료 기준은 서버 시각이다.
- `만료 안 함`은 운영자가 데이터를 지우기 전까지 유지한다.
- QR은 별도 저장 데이터가 아니라 공유 URL의 표현이다.
- 익명 생성·수령은 임시 MVP 제약이 아니라 제품 동작이다. 사용자 계정과 업로드 로그인은 범위에 넣지 않는다.

## 후속 배포 시스템에서 다룰 사항

- Docker와 공개 배포는 현재 범위에서 제외한다. 익명 업로드·다운로드는 유지하되, 공개 인터넷 배포 시에는 디스크 quota, 동시 요청 제한, TLS, 관측, 신고·차단 등 악용 대응을 별도 배포 시스템에서 마련한다. 6자리 코드는 수령 편의 코드이지 비밀키가 아니다.
